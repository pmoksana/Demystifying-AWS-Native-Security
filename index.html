Operational Reality: How Workflows Change

Traditional Multi-Vendor Environment
  • Vendor A (Scanner) flags an unpatched server on one dashboard.
  • Hours later, Vendor B (EDR) catches a suspicious file download on another console.
  • Manual Bottleneck: Analysts must log into both portals, manually cross-reference IP addresses and timestamps, and correlate alerts by hand.
AWS-Native Ecosystem
  • Amazon Inspector flags an unpatched vulnerability on an EC2 instance.
  • Amazon GuardDuty detects active exploitation on that exact server.
  • Automated Pipeline: AWS Security Hub instantly correlates both events into a high-priority alert and triggers an AWS Lambda script to isolate the host immediately.

The 3 Pillars of Cloud Security Operations

1. SIEM & Central Visibility

Aggregating, correlating, and analyzing log data across all accounts.
2. Vulnerability Management

Continuously scanning compute, containers, and code for CVEs and misconfigurations.
3. EDR & Threat Detection

Real-time runtime monitoring and behavioral anomaly detection.

AWS SIEM Part 1: AWS Security Hub

Features
  • Single Pane of Glass: Collects, normalizes, and aggregates alerts across multi-account AWS environments.
  • Automated Standards: Evaluates accounts against CIS Benchmarks and PCI-DSS automatically.
Value to Squads
  • Eliminates context-switching between disparate third-party vendor consoles.
  • Standardizes alert formatting using AWS Security Finding Format (ASFF).
  • Compliance Mapping: ISO 27001 / SOC 2 Continuous Audit Readiness.

AWS SIEM Part 2: Amazon Detective & OpenSearch SIEM

Amazon Detective
  • Root-Cause Analysis: Automatically maps complex event chains across VPC Flow Logs, CloudTrail, and GuardDuty.
  • Graph-Based Visualization: Visualizes relationships between compromised IP addresses, IAM roles, and EC2 instances.
SIEM on AWS OpenSearch
  • Open-Source Solution: AWS-published architecture for full custom log ingestion.
  • Deep Correlation: Custom dashboarding and long-term retention for enterprise forensic queries.

Continuous Vulnerability Scanning: Amazon Inspector

EC2 Instance Scanning

Automated software vulnerability (CVE) discovery with zero agent overhead option.

ECR Container Scanning

Scans container images on push and continuously monitors registries.

AWS Lambda Functions

Scans serverless code and third-party package dependencies for vulnerabilities.

Intelligent Risk Scoring

Contextualized risk scores based on real network accessibility (VPC route analysis).

Continuous Compliance Monitoring: AWS Config

How It Works
  • Continuous Resource Tracking: Records detailed configuration history of every AWS asset.
  • Drift Detection: Flags unauthorized changes that violate infrastructure-as-code baseline.
Common Rules
  • Rule: Enforce S3 Bucket Private Access (Block public read/write).
  • Rule: Ensure MFA enabled on root and privileged IAM accounts.
  • Rule: Verify EBS volume encryption at rest.

EDR & Continuous Threat Detection: Amazon GuardDuty

Intelligent Analysis

Uses Machine Learning and threat intelligence to analyze AWS data streams.

Multi-Layer Coverage

Monitors CloudTrail events, VPC Flow Logs, DNS logs, S3 access, and IAM activity.

Anomaly Detection

Catches compromised credentials, data exfiltration, and unauthorized API calls in real time.

Advanced Threat Defense: GuardDuty Runtime Monitoring

Scope
  • EKS & Kubernetes: Monitors container-level runtime file, process, and network connections.
  • EC2 & Serverless: Lightweight runtime monitoring agent tracking operating system behavior.
Capability
  • Detects reverse shell execution, privilege escalation, and unauthorized process spawning inside containers.
  • Operates as a native lightweight EDR agent without heavy performance overhead.

The Integrated AWS Security Stack Workflow

1
Stage 1 (Proactive Defense)

Amazon Inspector continuously scans EC2/ECR for CVEs and flags unpatched exposure.

2
Stage 2 (Threat Detection)

Amazon GuardDuty catches an active exploitation attempt or suspicious connection in real time.

3
Stage 3 (Central Response)

AWS Security Hub correlates both findings into one high-priority ticket for SOC action.

Incident Investigation Lifecycle in AWS

1

Step 1 (Alerting): GuardDuty flags unauthorized API call from an unknown foreign IP.

2

Step 2 (Aggregation): Security Hub ingests alert, applies severity score, and triggers EventBridge rule.

3

Step 3 (Investigation): Engineer opens Amazon Detective to visualize historical API activity and blasted IAM role.

4

Step 4 (Remediation): Automated AWS Lambda function revokes compromised IAM session keys instantly.

Real-World Attack Scenario: S3 Bucket Exfiltration

Attack Chain

Malicious actor steals exposed IAM access key from developer repository $\rightarrow$ Scans S3 buckets $\rightarrow$ Begins downloading sensitive customer datasets.

AWS Native Response

GuardDuty detects unusual data access pattern from unrecognized IP $\rightarrow$ Security Hub raises critical alert $\rightarrow$ AWS Config detects S3 policy modification.

Real-World Attack Scenario: Container Compromise

Attack Chain

Unpatched application vulnerability exposed to internet $\rightarrow$ Attacker gains remote code execution on EKS pod $\rightarrow$ Spawns crypto-miner.

AWS Native Response

Inspector flagged unpatched CVE during build phase $\rightarrow$ GuardDuty Runtime Monitoring detects unauthorized binary execution inside container pod in real time.

Training Summary & Best Practices for Squads

Key Takeaways
  • 1. Centralize visibility: Turn on Security Hub across all organizational accounts.
  • 2. Scan continuously: Use Inspector to catch vulnerabilities *before* code reaches production.
  • 3. Automate response: Connect GuardDuty findings to automated EventBridge remediation actions.
  • 4. Investigate fast: Use Amazon Detective to trace root causes in minutes, not days.
